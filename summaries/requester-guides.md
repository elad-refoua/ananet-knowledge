## Document 02: Purchase Requisition Screen - General Overview (מסך דרישות רכש - הסבר כללי)

**Pages:** 10 | **Scope:** Complete overview of the main purchase requisitions screen layout, navigation, menus, and functionality of every button/area.

### Topics Covered

#### 2.1 Login and Navigation
- **SSO Login:** Connect to Ananet via SSO (Single Sign-On)
- **Language Setting:** In the language selection field (בחר שפה), confirm language is set to **Hebrew - עברית**, then click **Connect (התחבר)**
- **Home Screen (מסך הבית):** Displayed after login
- **Module Navigation:** Navigate in the module bar (סרגל המודולים) and click **Procurement (רכש)**
- **Procurement menus** are displayed on the workspace (שולחן העבודה)
- Click **Purchase Requisitions (דרישות רכש)** to display the Purchase Requisitions home page

**Navigation Path:** `SSO Login > Home > רכש (Procurement) > דרישות רכש (Purchase Requisitions)`

#### 2.2 Purchase Requisitions Screen Layout
The screen is divided into multiple areas and menus:

1. **Manage Requisitions link (ניהול דרישות רכש):** Located top-left. Opens a new screen to search existing requisitions by various criteria. Click **Done (בוצע)** to close and return.

2. **Shopping Cart icon (עגלת הקניות):**
   - Clicking displays a pane listing requisition lines currently in the cart (not yet submitted as a requisition)
   - **Review/Edit button (בדיקה/עריכה):** Opens Edit Purchase Requisition screen with all cart lines
   - **Submit button (שליחה):** Opens Edit Purchase Requisition screen along with an error pane indicating missing data (e.g., requester phone, attribute value). Close the error pane and continue editing.

3. **Additional Tasks (משימות נוספות) menu:**
   - **Enter Purchase Requisition Line (הזן שורת דרישת רכש):** Opens a screen to add a single line to the shopping cart as an intermediate step before creating the full requisition
   - **Update Requisition Preferences (עדכן העדפות דרישת רכש):** Set default preferences that auto-populate every new requisition created by the user. Can be overridden per requisition.
     - **Deliveries and Handoffs (משלוחים ומסירות):** Update default requester and delivery address
     - **Billing - Projects (חיוב - פרויקטים):** Do NOT fill in a fixed project in requisition preferences
     - **Billing - Preferred Charge Accounts (חיוב - חשבונות צבירת חיובים מועדפים):** Update default budget account. Click **+** to add a row, then click the account icon to select. Can add multiple accounts and mark one as **Primary (ראשי)**.

4. **Shop by Category (קנה לפי קטגוריה):** Located top-right. Opens a hierarchical category list to browse and find items by category. Select a category to see its items, choose a product, update quantity, and click the cart icon to add.

5. **Search Bar (שורת החיפוש):** Search for items from catalogs/price lists maintained in the system. Eliminates the need for separate supplier searches or price quote requests.

6. **Smart Forms (טפסי בקשה):** Area displaying specialized requisition types, each with unique fields and processes. Clicking any form type opens its specific requisition screen.

7. **Recent Purchases (רכישות אחרונות):** Two panes:
   - **Right pane:** Recent requisitions created by the user
   - **Left pane:** Recent items that became purchase orders
   - Click **Show More (הצג עוד)** on the right pane to open Manage Requisitions search
   - Click **Show More** on the left pane to see recent items that were ordered and approved

8. **Top Categories (קטגוריות מובילות):** Shows leading product/service categories. Clicking any shows items with option to add to cart.

9. **Recently Viewed (הוצגו לאחרונה):** Shows recently used requisition types. Clicking any opens the relevant form.

## Document 03: Managing Purchase Requisitions (ניהול דרישות רכש)

**Pages:** 9 | **Scope:** Operations on existing requisitions regardless of type -- searching, actions based on status, approval workflow management.

### Topics Covered

#### 3.1 Searching Purchase Requisitions

**Navigation Path:** `רכש (Procurement) > דרישות רכש (Purchase Requisitions) > ניהול דרישות (Manage Requisitions)`

**Search Types:**
- **Basic Search (חיפוש בסיסי):** Value fields only. Some allow selection from dropdown (small arrow), others use magnifying glass search which opens a new search pane (also with basic/advanced toggle)
- **Advanced Search (חיפוש מתקדם):** Adds operator column enabling:
  - **Equals (שווה ל):** Exact match
  - **Contains (מכיל):** Partial match anywhere
  - **Starts With (מתחיל ב):** Match at beginning
  - **Ends With (מסתיים ב):** Match at end
  - Operators vary by field type
- **Add Fields (הוסף שדות):** In advanced search, add additional search fields from dropdown. Added fields show an X for removal
- **Reorder (סדר מחדש):** Rearrange search fields using up/down arrows or beginning/end buttons (|> and |<)
- **Saved Searches:** Save frequently used searches:
  1. Enter search criteria
  2. Click **Save (שמירה)**
  3. Name the search
  4. Optionally set as default search and/or auto-run on screen entry
  5. Click **OK (אוקיי)**

**Important Note:** The search mechanism described here is generic and works the same way across all Ananet screens and fields.

#### Search Results Actions

| Action | Conditions | Result |
|---|---|---|
| **Duplicate (שכפל)** | Single row selected; created by you; has lines | Opens new requisition with new number and same data |
| **Export to Excel (יצא לאקסל)** | Any status, any creator | Opens Save As dialog |
| **Cancel Requisition (ביטול הדרישה)** | All statuses except "Not Completed" and "Cancelled" | Prompts for cancellation reason; status changes to Cancelled |
| **Withdraw and Edit (הסר וערוך)** | Pending Approval status; or Approved with cancelled lines (blue icon indicator) | Warning shown; removes from approval flow; opens edit screen; status becomes Withdrawn |
| **Delete (מחיקה)** | Single row; created by you; "Not Completed" status only | Warning shown; permanent deletion |
| **Edit (עריכה)** | Single row; "Not Completed" or "Rejected" status only | Opens in edit mode |
| **Reassign (הקצאה מחדש)** | Any status; only if created by you | Opens user selection pane; choose new owner and click OK |
| **View Document History (הצג היסטוריית מסמך)** | Any status; requisition must have lines | Shows all stages the requisition has gone through |

#### 3.2 Actions Within a Requisition

Actions available in statuses **Not Completed (לא הושלם)** or **Pending Approval (ממתין לאישור)**:

1. **Duplicate (שכפול):** Actions > Duplicate. New requisition with new number and identical data.
2. **Delete (מחיקה):** Click Delete. Permanent deletion with warning confirmation.
3. **Edit (עריכה):** Click Edit. **Only available when status is "Not Completed."** Not available when Pending Approval or Approved.
4. **Reassign (הקצאה מחדש):** Transfer ownership. Search/select user, optionally send notification, click OK.
   - After reassignment, the "Entered By (הוזן על ידי)" field shows the new user; "Requester (מבקש)" still shows original creator
   - **Permissions vary by role:** Requester can only reassign own requisitions. Overseas buyer can reassign others' requisitions.
5. **View Document History (הצגת היסטוריית מסמך):** Shows all stages from creation through approvals, reservation, reassignment, cancellation requests, and conversion to transfer order or purchase order.
   - Clicking the number in the **Reference Document (מסמך אסמכתא)** column opens the relevant screen with full details.

#### Actions on Approved Requisitions (סטטוס אושר)
- **Cancel Requisition (ביטול הדרישה):** Find the requisition > click requisition number > Actions > Cancel Requisition > Enter cancellation reason > OK
- Confirmation message displayed and action added to document history.

## Document 04: Purchase Requisitions - Inventory (דרישות רכש - מלאי)

**Pages:** 19 | **Scope:** Complete process for ordering items from the main warehouse inventory.

### Process Overview
The requester selects inventory-managed items from the warehouse, submits for standard approval, and after approval the requisition **automatically converts to a Transfer Order (הוראת העברה / Internal Shipment)**. After the warehouse reports dispatch, the budget account is debited without generating an invoice.

### Process Flow
1. Create requisition line > 2. Update data and attachments > 3. Submit for approval > 4. Approval > 5. Transfer Order created automatically > 6. Warehouse picks and ships

#### 4.2 Creating a Requisition Line

**Navigation:** `SSO Login > רכש > דרישות רכש`

**Step-by-step:**
1. Connect to Ananet via SSO
2. Navigate to Procurement > Purchase Requisitions
3. Click **Additional Tasks (משימות נוספות)** > **Enter Purchase Requisition Line (הזן שורת דרישת רכש)**
4. In **Line Type (סוג שורה)** field, verify value is **Requisition by Quantity and Price (דרישה לפי כמות ומחיר)**
5. In **Item (פריט)** field, click the magnifying glass (search)
6. Click **Advanced (מתקדם)**
7. Click **Add Fields (הוסף שדות)** and add the field **Internally Transferable (ניתן להעברה פנימית)**
8. Enter search data: Item (code/SKU) and/or Description; enter **Y** in Internally Transferable field; click **Search (חיפוש)**

**Important Note:** When the search pane has fields with double asterisks (**), at least one of those fields must contain a value.

**Required Fields Table:**

| Field (Hebrew) | Field (English) | Value | Required | Notes |
|---|---|---|---|---|
| סוג שורה | Line Type | דרישה לפי כמות ומחיר | Y | Do not change |
| פריט | Item | Select item | Y | When selected from inventory, Source Type auto-fills as "Inventory (מלאי)" |
| כמות | Quantity | Enter number | Y | |
| סוג מקור | Source Type | מלאי (Inventory) | Y | Auto-fills when inventory item selected |
| מחסן מקור | Source Warehouse | מחסן כללי (General Warehouse) | N | If entered, must be General Warehouse only |
| מבקש | Requester | Requester name | Y | Default = creator; can change for another user |
| האם הרכישה מוגדרת כתשומת מחקר או הוראה | Is purchase defined as research/teaching input | תשומה/לא תשומה | Y | Must have value but irrelevant for inventory |
| ערך תכונה | Attribute Value | אחר (Other) | Y | For inventory purchases, always select "Other" |
| מיקום יעד למסירה | Delivery Location | Select location | Y | Default from preferences; can change |
| סוג יעד | Destination Type | הוצאה (Expense) | Y | "Inventory (מלאי)" is for warehouse replenishment |

#### Charge Account (חיוב) Section
- Click the blue magnifying glass icon next to the Charge Account field
- Default account appears automatically
- To change: click **Reset (איפוס)** > confirm warning > click **Search (חפש)** to display assigned accounts > select > OK
- **Tooltip:** Hovering over any account row shows a pane with budget line details

**Warning:** The **Finish (סיום)** button at the top of the form acts as cancel/delete -- do NOT click unless you intend to discard the current line.

#### Account Splitting (פיצול חשבונות)
- Click the split icon above account rows to add another account line
- Update account details
- Split by percentage (אחוז), quantity (כמות), or amount (סכום) -- updating one field auto-updates the other two
- Total of percentage/quantity/amount must equal the line total
- Charge accounts apply to the selected line only, not the entire requisition

#### 4.3 Adding to Shopping Cart
1. Click **Add to Cart (הוספה לעגלה)** -- pop-up confirms successful addition
2. Repeat the process to add more items to the same requisition

#### 4.4 Shopping Cart
1. Click the **Shopping Cart** icon to view contents
2. **Delete row:** Click X on the left side of a row
3. **Submit (שליחה):** Shows Edit Requisition screen with phone number error
4. Click OK on error, enter phone number, then click **Submit (שלח)** to send for approval and warehouse transfer order creation
5. **Review (בדיקה):** Transfers all cart content to one requisition and opens Edit Requisition screen

#### 4.5 Editing the Purchase Requisition

**Main Menu Actions:**
- **Return to Cart (לעגלת הקניות):** Moves requisition content back to cart
- **Budget Balance Check (בדיקת יתרות תקציב):** Checks budget availability; shows confirmation or detailed results
- **Manage Approvals (ניהול אישורים):** View approval chain; add approvers (for information only or actual approval):
  1. Select a row in approval stages
  2. Ensure the add icon is active
  3. Click add icon; user selection pane appears
  4. Search for user, select position (information only or approver), click **Apply (החלה)**
  - **Warning:** Do not click Submit from this screen unless you have finished editing the entire requisition
- **View PDF (הצגת PDF):** Generate and save PDF of the requisition
- **Save (שמור):** Save changes without closing
- **Save and Close (שמור וסגור):** Save and close without submitting

**Note:** Available menu actions depend on requisition status and whether it is in edit mode.

**Header Fields (אזור כללי):**

| Field | Value | Required | Notes |
|---|---|---|---|
| תיאור (Description) | Meaningful description | Y | Default from first line item description |
| מספר סלולרי לאספקה (Cell Phone for Delivery) | Mobile number | Y | Number of actual recipient for supplier/warehouse coordination |
| מספר מלגה (Scholarship Number) | Number if applicable | Optional | Informational only |
| ערך תכונה (Attribute Value) | Select value | Y | Default = Other, unless specified differently at line creation |

**Line Actions:**
- **Duplicate:** Select row > Actions > Duplicate (or use icon above table)
- **Delete:** Select row > Actions > Delete (or use icon) -- no warning message
- **Edit:** Select row > Actions > Edit -- opens Edit Line pane; update and click OK
- **Edit Multiple Rows:** Select multiple rows > Edit Multiple Rows button -- any change applies to ALL selected rows
- **Update Quantity:** Directly edit quantity in the table row, then Save
- **Edit Additional Details:** Select row, scroll to area below table for line-specific data (delivery, expense type, charge account)

#### 4.6 Approval Process
Standard approval cycle. After approval, the requisition automatically converts to a Transfer Order (הוראת העברה).

**To withdraw and re-edit after submission:**
1. Find requisition via Manage Requisitions or Recent Purchases
2. Verify status is "Pending Approval"
3. Click requisition number > Actions > **Withdraw and Edit (הסר וערוך)**
4. Confirm warning > Save and Close
5. Status changes to "Withdrawn (הוסר)" -- indicator shown in lines and header
6. Re-enter > Actions > Edit > Make changes > Submit again

**After approval:** Document History shows the Transfer Order was created, completing the requester's role.

## Document 05: Purchase Requisition - Local Purchase (דרישת רכש - רכש מקומי)

**Pages:** 13 | **Scope:** Requisitions for items NOT in a price list, NOT hazardous, NOT from inventory, NOT imported.

### Process Overview
Requester enters one or more items from a single supplier based on a received price quote, submits for approval, and the requisition reaches the buyer who converts it to a purchase order to the supplier. Process ends with the requester reporting goods receipt.

### Process Flow
1. Price quote from supplier > 2. Build shopping cart > 3. Create requisition from cart > 4. Submit for approval > 5. Approval > 6. Buyer creates PO > 7. Supplier ships > 8. Report receipt

#### 5.2 Creating Requisition Lines

**Navigation:** `רכש > דרישות רכש > משימות נוספות > הזן שורת דרישת רכש`

**Header Fields:**

| Field | Value | Required | Notes |
|---|---|---|---|
| סוג שורה (Line Type) | דרישה לפי כמות ומחיר | Y | Do not change |
| פריט (Item) | Item SKU | N | Not required since price quote from supplier is mandatory |
| תיאור פריט (Item Description) | Description | Y | Auto-fills if SKU selected; can be changed |
| שם קטגוריה (Category Name) | Category | Y | Auto-fills if SKU selected; cannot be changed. To change: delete item and search for different one |
| כמות (Quantity) | Quantity | Y | As per price quote |
| שם יחידת מידה (UOM Name) | Select from list | Y | As per price quote |
| מחיר (Price) | Enter price | Y | Per unit as per price quote. **Note:** If SKU selected from system, price auto-fills but may not match the quote |
| מטבע (Currency) | Select currency | Y | Auto-fills if SKU selected; mostly ILS for local purchase |

**Delivery Section (מסירה):**

| Field | Value | Required | Notes |
|---|---|---|---|
| מבקש (Requester) | Requester | Y | Default = form filler; can change |
| סוג מיקום יעד למסירה (Delivery Location Type) | פנימי/חד פעמי (Internal/One-time) | Y | Internal = from system list; One-time = type manually |
| מיקום יעד למסירה (Delivery Location) | Select or type | Y | |
| האם הרכישה מוגדרת כתשומת מחקר או הוראה | תשומה/לא תשומה | Y | Selecting "Research Input (תשומה)" bypasses mandatory tender check |
| ערך תכונה (Attribute Value) | אחר/חומרים מסוכנים | Y | Controls which DFF fields are displayed |

**Supplier fields (optional):** Supplier name, Supplier site, Contact person -- buyer will finalize these at PO stage.

**Charge Account:** Same process as Document 04 (select, reset, search, split).

**Notes and Attachments (הערות ונספחים):**
- Notes to Buyer (הערות לקניין), to Supplier (לספק), to Recipient (למקבל)
- Each reaches the respective party

**Add to Cart:** Click Add to Cart > confirmation popup > repeat for more items.

#### 5.3 Shopping Cart
Same process: click cart icon > review > Delete rows with X > click Review (בדיקה) to create requisition and open edit screen.

#### 5.4 Editing the Requisition
Same as Document 04 section 4.5, with one critical addition:

**Attachments (נספחים) - MANDATORY for Local Purchase:**
- **A price quote from the supplier MUST be attached** -- otherwise the requisition will be rejected during approval.
- Steps to attach:
  1. Click the **+** sign next to Attachments (נספחים)
  2. "Attached Documents (מסמכים מצורפים)" pane appears
  3. Choose type: **File (קובץ)**, **URL**, or **Text (טקסט)**
  4. Select recipient category (קטגוריה)
  5. For File: Click Choose File > select > Open > add Title and Description > OK
  6. For URL/Text: select in Type column, fill in fields
  7. To add more: click **+** or Actions > Add
  8. To remove: click **X** or Actions > Delete
  9. After attachment, the Attachments field shows clickable links

#### 5.5 Approval Process

## Document 17: Purchase Requisition - Change Order After PO Creation (דרישת רכש - הוראת שינוי לאחר יצירת הזמנה)

**Pages:** 4 | **Scope:** Creating change orders (amendments) for existing purchase orders.

### Process Overview
A Change Order (הוראת שינוי) is a procedure for creating revision editions of existing purchase orders. It can only be applied to POs in statuses: **Open (פתוח)**, **Closed for Receiving (סגור לקבלה)**, or **Closed for Invoicing (סגור להוצאת חשבונית)**.

Change orders can be initiated two ways:
1. **By the requester** -- from the purchase requisition after a PO has been created
2. **By the buyer** -- directly in the purchase order

This document covers the requester's process.

### Process Flow
1. Need for PO update arises > 2. Requester creates change order from requisition > 3. Approval of change order > 4. PO approval of change order

#### Important Conditions

- **Only the requester who created the requisition** (or the assignee) can create a change order
- The buyer can assign the requisition to themselves, make changes, then reassign to the original requester for review and submission
- **Requisition not yet converted to PO:** The requester can simply withdraw and edit (no change order needed)
- **Requisition with a single line that has a PO:** Change order created from the requisition's main Actions menu > **Edit Order (עריכת הזמנה)**
- **Requisition with multiple lines, only some with POs:** Change order created at the line level: select the specific line > Actions > **Edit Order (עריכת הזמנה)**

#### 17.2 Creating a Change Order

**Step-by-step:**
1. Navigate to: `רכש > דרישות רכש > ניהול דרישות`
2. Search for the requisition
3. Verify status is: Approved (מאושר), Closed for Receiving (סגור לקבלה), or Closed for Invoicing (סגור להוצאת חשבונית)
4. Click the requisition number to open it
5. Click **Actions (פעולות)** > **Edit Order (עריכת הזמנה)**
6. Warning message displayed before creating the change order
7. Click **Yes (כן)**
8. **Edit Change Order screen** displayed (עריכת הוראת שינוי: מס' X)
9. Enter description and make the required changes
10. Click **Submit (שלח)**
11. Confirmation displayed that the change order has been sent for approval

## Key Warnings and Tips (Across All Documents)

1. **Finish (סיום) button = Cancel:** On the "Enter Requisition Line" form, clicking Finish deletes/cancels the current line data. Do NOT click unless intentional.

2. **Shopping Cart is all-or-nothing:** Cannot select specific rows from the cart -- all content becomes one requisition. Delete unwanted rows before or after.

3. **Price list items cannot be edited:** Lines from price list/catalog are part of a supplier agreement and cannot be modified. Attempting to edit shows an error.

4. **Account split notes:**
   - Charge accounts apply per line, not per requisition
   - Updating percentage, quantity, or amount auto-updates the other two
   - Totals must match the requisition line total

5. **Approval timing:** Can take minutes to days depending on number/identity of approvers, monetary value, and category.

6. **Withdraw and re-edit:** Only possible when status is "Pending Approval." After withdrawal, status becomes "Withdrawn" and the requisition can be edited and resubmitted.

7. **Change orders:** Only the original requester (or assignee) can create change orders from the requisition.

8. **Hazardous materials:** Lab code is personal -- keep it secure. Contact Safety Department if lost.

9. **BIRAD requisitions:** Price must be set to 0.00.

10. **Transportation:** One vehicle per requisition, even if the trip involves multiple vehicles.

11. **Double-asterisk fields (**) in search:** At least one such field must have a value for the search to execute.

12. **Research input flag (תשומה):** Setting this bypasses the mandatory tender law check (חוק חובת המכרזים). Must be set accurately.
